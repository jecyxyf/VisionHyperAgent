# 项目文档路由

AGENTS.md 只负责路由，不承载项目规则本身。每次执行任务前，先根据任务类型读取对应文档，并把其中的规则作为本次任务的执行约束。

## 路由表

| 任务类型 | 必读文档 |
| --- | --- |
| 前期对话、需求澄清、产品范围或需求调整 | [project-requirement]({{需求技能路径}})、[产品需求文档](specs/REQ-001-产品需求文档.md) |
| 技术选型、架构分层、模块职责或依赖的设计与调整 | [project-requirement]({{需求技能路径}})、[产品需求文档](specs/REQ-001-产品需求文档.md)、[技术方案设计](specs/REQ-002-技术方案设计.md) |
| 设计或修改数据结构、公开接口、消息、委托及跨模块契约 | [project-requirement]({{需求技能路径}})、[技术方案设计](specs/REQ-002-技术方案设计.md)，以及 [模块 API 目录](specs/models/) 中对应模块的文档 |

| 制定或更新开发计划与进度 | [project-requirement]({{需求技能路径}})、[模块 API 目录](specs/models/) 中涉及的契约；已有计划时读取 [开发计划及进度](specs/plans/开发计划及进度.md)，仅更新任务和实际进展 |
| 继续未完成的需求设计流程 | [project-requirement]({{需求技能路径}}) 和本次受影响的正式需求、技术方案或 API 文档；开发计划不记录设计阶段状态 |

## 调用规则

1. 只读取当前任务需要的文档。模块 API 按架构层和模块名定位，具体位置见项目结构文档，不一次加载全部模块。
2. 跨阶段任务按实际涉及的任务类型组合读取。纯查阅不启动访谈；任务需要改变已确认方案时，切换到对应设计变更路由。
3. 目标文档缺失或不可读取时，明确指出，不把示例、猜测或无效链接当成项目规则。生成路由时删除未创建的可选开发计划链接，待计划实际生成后再补入。
4. 文档规则与用户当前明确要求冲突时，先确认处理方式。
5. 本文件不总结、复制或改写项目规则，规则变更修改对应文档。
6. 编码和接口接入前读取本次相关的正式 API、技术方案和代码规范；已有开发计划时另查任务及实际进度，不能从任务状态推断设计确认。正式契约待确认、待更新或相互冲突时，转需求技能处理受影响设计，不直接按旧契约实施。纯查询和只读审查可以继续，但须说明所读版本的状态，不重新启动整套规划。
