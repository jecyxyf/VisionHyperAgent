# 项目工作入口

> 模板使用说明：生成项目根目录的 `AGENTS.md` 时，先读取已有文件并合并有效规则；将主、子技能路径替换为目标项目可访问的实际路径，核对文档链接，删除本段说明及不存在的可选文档链接。不要把模板中的路径当作已创建文件。

本文件负责工作流程和文档路由。产品行为、技术决定及代码规范以对应的已确认文档为准，不在这里重复其正文。

## 文档路由

| 任务 | 入口与应读内容 |
| --- | --- |
| 从初始化开始或继续 EasyCode 完整流程 | [easycode]({{主技能路径}})；按当前阶段检查环境、确认记录和相关正式文档 |
| 检查、安装或修复 2119 与 hooks | [easycode]({{主技能路径}}) 的初始化说明及目标项目现有配置；写入前取得同意 |
| 讨论、创建或修改产品需求 | [easycode-product]({{产品技能路径}})；按技能要求检查并读取 `specs/REQ-001-产品需求文档.md` |
| 讨论、创建或修改技术方案 | [easycode-technical]({{技术技能路径}})；读取已确认的产品需求和现有 `specs/REQ-002-技术方案设计.md` |
| 按已确认方案生成项目结构、模块 API、开发计划、代码规范或 AGENTS | [easycode]({{主技能路径}})；读取相关已确认文档及目标项目已有规则，按获批范围执行 |
| 编码、修改、测试或继续开发 | 读取 `specs/plans/开发计划及进度.md`、相关技术方案、模块或组件的有效接口文档、代码规范，以及受影响的现有代码和测试 |
| 只读查询或审查 | 只读取本次问题相关的文档、代码和实际证据；不因查询启动文档生成或编码 |

只读取当前任务涉及的文档，不一次加载所有模块。设计、接口或任务依据缺失、待确认或互相冲突时，指出具体问题，先确认或修订受影响的文档，不把猜测当作已批准的开发依据。

## 编码阶段

1. 开始或续做时，先核对开发计划中相关任务、代码、测试结果和工作区现状，区分计划记录与真实进度；中断后也重新核对，不凭上次对话或任务状态直接续写。
2. 动手前明确本轮要完成的阶段及其任务边界。若计划没有阶段划分，先请用户确定本轮包含哪些任务；不能自行把全部未完成任务视为本轮范围。
3. 写入代码、文档或进度前，先给出本轮完整的执行计划，包括修改范围、实施顺序和核对方式，取得用户明确同意；仅执行获批范围内的操作。
4. 在获批阶段内，按开发计划逐项实现、验证并依据真实证据更新任务进度。未通过的测试、未完成的验收和客观阻碍如实记录，不把文件存在当成任务完成。
5. 本轮阶段完成后立即停下，汇报完成内容和剩余问题，等待用户确认下一阶段。即使仍有未完成的开发计划或持续中的 goal，也不自动进入下一阶段。
6. 开发中发现需求、技术方案或接口需要改变时，先指出影响并按对应文档路由确认；不在编码阶段自行改写已确认的设计。未经用户明确要求，不执行 Git 提交或推送。
