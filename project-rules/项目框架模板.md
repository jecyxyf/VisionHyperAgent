# <项目名称> 软件框架设计文档

> 本模板的章节层级、架构图、流程图和表格形式沿用《软件框架设计.md》。内容统一使用虚构的 ImageBatch 图片批处理项目作为 Demo，不描述当前仓库的实际实现。

## 1. 概述

### 1.1 软件定位

ImageBatch 是一个图片批处理桌面工具，支持图片导入、参数配置、批量缩放、灰度处理和结果导出。用户可以保存工程，在下次打开时恢复输入图片和处理步骤。

本 Demo 用 **导入 → 配置 → 处理 → 查看结果** 的完整流程说明主程序、控件库、界面逻辑库、算法库、对象模型库和通用库之间如何协作。

### 1.2 核心目标

| 目标 | 说明 |
|------|------|
| 批量处理 | 对选中的图片依次执行缩放、灰度等操作 |
| 交互反馈 | 展示当前任务、处理进度、成功结果和失败原因 |
| 工程恢复 | 保存图片引用、操作参数和输出目录，重新打开后恢复编辑状态 |
| 扩展能力 | 允许受信任插件增加水印等可选滤镜 |
| 跨平台 | 示例以 Windows / Linux 桌面应用为目标 |

### 1.3 技术栈

| 类别 | 选型 |
|------|------|
| 编程语言 | C++17 |
| 构建系统 | CMake + Ninja |
| 编译器 | Windows 使用 MSVC；Linux 使用 GCC |
| UI 框架 | Qt 6 |
| 图像处理 | OpenCV 4 |
| 工程与配置格式 | JSON，使用 nlohmann/json |
| 日志 | spdlog |
| 单元测试 | GoogleTest |

### 1.4 设计原则

**分层隔离**：主程序组合 UI，UI 对接 ViewModel；ViewModel 协调 Algo 与 Object，二者使用 Common 提供的公共能力。Algo 与 Object 并列，不相互依赖，也不引用上层界面。

**接口优先**：通过 Algo 中的 IImageFilter 统一内置与插件滤镜的调用方式，ViewModel 不绑定某个具体滤镜实现。

**边界清晰**：OpenCV、JSON 和日志库的具体类型留在所属模块内部；跨层传递自有数据类型。Qt Core 允许用于 ViewModel，Qt Widgets / Gui 仅用于 UI 和应用入口。

**插件友好**：缩放、灰度是内置能力；可选水印滤镜由插件提供。插件缺失不影响内置滤镜，但依赖该插件的任务不能执行。

**可测性**：Algo 与 Object 不依赖 Qt；ViewModel 可以使用 Qt Core，但不创建控件，可在不启动图形界面的条件下测试。

## 3. 模块职责划分

### 3.1 Common — 通用库

**定位**：提供与具体批处理业务无关的公共能力，不引用 UI、ViewModel、Algo 或 Object。

| 具体类 | 职责说明 | 归属三方库 |
|------|------|------|
| `AppLog` | 统一日志入口，记录导入、处理、保存及插件错误 | spdlog |
| `AppSettings` | 管理输入目录、输出目录和插件目录等配置 | nlohmann/json |
| `ImageBuffer` | 自有像素缓冲类型，只包含尺寸、通道和像素数据 | 无 |

> **归属原则**：日志、应用配置和独立像素缓冲属于 Common；任务状态、操作序列等业务数据属于 Object。

### 3.2 Algo — 算法库

**定位**：封装图片读写和处理算法。编解码接口接收图片路径，滤镜接口接收像素与参数；不操作任务对象、工程描述文件或界面。

| 具体类 | 职责说明 | 归属三方库 |
|------|------|------|
| `IImageFilter` | 统一图像处理接口，接收像素缓冲和处理参数 | 无 |
| `ResizeFilter` | 实现 IImageFilter，按目标尺寸缩放图片 | OpenCV |
| `GrayscaleFilter` | 实现 IImageFilter，将彩色图片转换为灰度图片 | OpenCV |
| `ImageCodec` | 读取和保存图片，转换图像库类型与 ImageBuffer | OpenCV |
| `FilterRegistry` | 按处理标识注册和查找滤镜，管理其有效生命周期 | 无 |

> ImageCodec 在内部转换 OpenCV 类型与 ImageBuffer。ViewModel 将 Object 中的操作参数转换为滤镜调用参数，Algo 不直接引用 Object。

### 3.3 Object — 对象模型库

**定位**：定义工程中的图片、处理操作和批处理任务。对象保存数据和业务状态，不承担文件读写或 UI 刷新。

#### 继承层次总览

```
ProjectNode                  ← 标识与名称
├── ImageItem                ← 图片路径与尺寸
├── OperationBase            ← 操作标识与参数
│   ├── ResizeOperation      ← 目标宽高
│   ├── GrayscaleOperation   ← 灰度处理参数
│   └── PluginOperation      ← 扩展滤镜标识与参数
└── BatchTask                ← 批处理任务

组合关系：BatchTask 引用多个 ImageItem，并持有有序的 OperationBase 集合。
任务状态：待运行 → 运行中 → 成功 / 失败 / 已取消。
```

#### 各层职责说明

**基类层**

| 类 | 职责说明 |
|------|------|
| `ProjectNode` | 提供稳定的对象 ID 和名称，供工程保存与引用使用 |
| `OperationBase` | 提供滤镜标识与参数约定；表示“要执行什么”，不执行算法 |

**图像子分区（继承 ProjectNode）**

| 类 | 职责说明 | 归属三方库 |
|------|------|------|
| `ImageItem` | 记录源文件路径与尺寸，不保存 cv::Mat、QImage 或 UI 控件 | 无 |

**操作子分区（继承 OperationBase）**

| 类 | 职责说明 | 归属三方库 |
|------|------|------|
| `ResizeOperation` | 保存目标宽高，使用处理标识 resize | 无 |
| `GrayscaleOperation` | 保存灰度处理参数，使用处理标识 grayscale | 无 |
| `PluginOperation` | 保存扩展处理标识及其参数，例如 watermark | 无 |

**任务子分区（继承 ProjectNode）**

| 类 | 职责说明 | 归属三方库 |
|------|------|------|
| `BatchTask` | 组合输入图片引用、操作顺序和输出目录，记录进度、状态及错误；由 ViewModel 统一更新 | 无 |

**其他预留分区**

| 类别 | 说明 |
|------|------|
| 处理预设 | 后续可将常用操作序列保存为独立模板 |
| 导出策略 | 后续可扩展文件命名、格式和质量设置 |

### 3.4 ViewModel — UI 逻辑库

**定位**：连接控件与业务对象，协调导入、任务执行、工程读写及插件管理；不直接实现图像算法。

| 具体类 | 职责说明 |
|------|------|
| `VmImageIO` | 将图片导入工程 input/，调用解码模块并创建图像对象 |
| `VmTaskManager` | 管理任务集合、选中任务和任务状态 |
| `VmBatchRunner` | 协调后台处理、取消请求与处理结果回传 |
| `VmProjectManager` | 管理工程读写及插件加载、注册和释放 |

> ViewModel 可以使用 Qt Core 信号/槽和后台任务设施，但不创建 QWidget 或 QImage。后台处理结果通过排队通知回到 ViewModel 所在线程后更新对象，UI 控件只在 GUI 线程刷新。

### 3.5 UI — 控件库

**定位**：负责输入与展示，对接 ViewModel 暴露的状态和命令，不直接创建滤镜或修改任务对象。

| 具体类 | 职责说明 | 归属三方库 |
|------|------|------|
| `UiImageList` | 图片列表与导入入口，展示图片名称和尺寸 | Qt Widgets |
| `UiTaskPanel` | 处理参数、开始/取消按钮与进度展示 | Qt Widgets |
| `UiPreview` | 显示输入图片和处理结果预览 | Qt Widgets / Qt Gui |

> UiPreview 在 UI 内部将 ViewModel 提供的 ImageBuffer 转为显示用图像；OpenCV 类型不进入 UI 接口，控件类型也不进入下层模块。

### 3.6 ImageBatch — 主程序

**定位**：应用入口和装配位置，负责初始化、连接模块及退出清理，业务协调留在 ViewModel。

| 子模块 | 职责说明 |
|------|------|
| 应用启动 | 创建 Qt Application，初始化 AppLog / AppSettings，注册 resize 与 grayscale 内置滤镜 |
| 主窗口 | 组合 UiImageList、UiTaskPanel、UiPreview，并连接对应 ViewModel |
| 退出清理 | 请求停止新任务，等待后台工作结束，销毁插件滤镜实例，再卸载动态库并关闭日志 |

## 4. 三方库集成策略

### 4.1 OpenCV

| 项目 | 说明 |
|------|------|
| 集成位置 | Algo：ImageCodec、ResizeFilter、GrayscaleFilter |
| 集成方式 | 通过 Algo 的私有构建依赖链接所需模块 |
| 隔离策略 | 对外使用 ImageBuffer，不在公共接口中暴露 cv::Mat |
| 依赖链 | OpenCV 由构建环境提供；UI 与 Object 不直接链接或引用其接口 |
| 初始化 | 由 Algo 初始化所需资源，不在业务对象构造时触发全局初始化 |
| 版本锁定 | 宿主及插件使用一致的项目锁定版本，不在模板中写入本机安装路径 |

### 4.2 Qt

| 项目 | 说明 |
|------|------|
| 集成位置 | ViewModel 使用 Core；UI 和 ImageBatch 使用 Widgets / Gui |
| 集成方式 | 按模块分别链接需要的 Qt 组件 |
| 隔离策略 | Algo、Object、Common 不依赖 Qt；Qt 控件和显示图像不出现在下层接口 |
| 线程边界 | 后台只进行数据处理，控件更新回到 GUI 线程执行 |

### 4.3 nlohmann/json

| 项目 | 说明 |
|------|------|
| 集成位置 | Common 的 AppSettings；ViewModel 的 VmProjectManager |
| 集成方式 | 作为所属模块的私有头文件依赖 |
| 隔离策略 | 配置接口和 Object 不暴露 JSON 库类型，由读写模块完成字段映射 |

### 4.4 spdlog

| 项目 | 说明 |
|------|------|
| 集成位置 | Common 的 AppLog |
| 集成方式 | 通过 Common 的私有依赖接入 |
| 隔离策略 | 上层调用 AppLog，不直接持有第三方 logger |

### 4.5 GoogleTest

| 项目 | 说明 |
|------|------|
| 集成位置 | 独立测试工程 |
| 集成方式 | 仅测试目标链接，不随业务库接口向外暴露 |
| 隔离策略 | 覆盖滤镜参数、任务状态、工程读写和插件缺失等场景，不要求创建 UI 控件 |

### 4.6 三方库归属一览

| 库名 | 归属层 | 集成方式 |
|------|------|------|
| OpenCV | Algo | 私有链接，使用自有像素类型隔离 |
| Qt Core | ViewModel / UI / ImageBatch | 按模块链接 |
| Qt Widgets / Gui | UI / ImageBatch | 仅用于界面及应用入口 |
| nlohmann/json | Common / ViewModel | 私有头文件依赖 |
| spdlog | Common | 通过 AppLog 封装 |
| GoogleTest | 测试工程 | 仅测试目标链接 |

## 5. 插件机制设计

### 5.1 插件加载流程

```
ImageBatch 启动并注册内置滤镜
    │
    ▼
VmProjectManager 读取 AppSettings 中的插件目录
    │
    ▼
检查受信任插件清单、接口版本和构建兼容信息
    │
    ▼
加载动态库 → 查找 CreateImageFilter() / DestroyImageFilter()
    │
    ▼
创建 IImageFilter 实例 → 注册到 FilterRegistry
    │
    ▼
VmBatchRunner 按处理标识调用滤镜，例如 watermark

退出时：停止任务 → 注销滤镜 → 用配对销毁函数释放实例 → 卸载动态库
```

### 5.2 插件安全约束

- **ABI 一致性**：工厂函数采用 C 导出符号，返回 IImageFilter 接口；本 Demo 要求宿主与插件的编译器、标准库及运行库配置一致，不把 C 导出符号等同于任意 C++ ABI 兼容。

- **版本检查**：加载前验证插件的接口版本和处理标识；版本不符或标识重复时拒绝注册。

- **错误处理**：校验失败或可捕获的加载、调用错误会记录日志；依赖不可用插件的任务明确报错，不静默跳过操作。

- **信任与生命周期**：这里只支持可信的进程内插件，不承诺隔离插件崩溃；滤镜实例及后台任务结束前不得卸载所属动态库。

## 6. 场景与数据流

### 6.1 工程文件格式

本 Demo 使用工程目录加 JSON 描述。工程文件记录格式版本、图片相对路径、操作参数和输出目录，不保存像素缓存、控件或运行中的线程对象。

```
<工程目录>/
├── project.ibproj.json     — 工程版本、图片引用、任务与操作序列
├── input/                  — 导入图片
│   ├── photo-01.png        — 输入图片示例
│   └── photo-02.png
└── output/                 — 处理结果，不覆盖输入文件
    └── <任务ID>_<图片ID>.png
```

### 6.2 工程加载流程

```
用户打开 project.ibproj.json
        │
        ▼
ViewModel：VmProjectManager
    检查格式版本、解析字段、校验文件路径与对象引用
        │
        ▼
Object 对象重建（先在临时集合中完成）
    ├── 创建 ImageItem
    ├── 创建 ResizeOperation / GrayscaleOperation / PluginOperation
    └── 创建 BatchTask，恢复图片引用与操作顺序
        │
        ▼
ViewModel 状态重建
    ├── VmTaskManager 绑定任务集合
    ├── VmImageIO 按需请求 ImageCodec 读取预览
    └── VmBatchRunner 校验所需滤镜是否已注册
        │
        ▼
UI 控件层刷新
    ├── UiImageList 显示图片
    ├── UiTaskPanel 显示参数与可执行状态
    └── UiPreview 显示预览

解析或引用校验失败：保留原工程，报告错误。
输入文件或插件缺失：保留工程信息，由 ViewModel 提供不可执行原因，不新增任务运行状态。
重新打开工程只恢复编辑配置，任务回到待运行，不自动重启处理。
```

### 6.3 批处理运行时数据流

```
UiTaskPanel 触发“开始”
        │
        ▼
VmBatchRunner 校验参数和滤镜，任务切换为运行中
        │
        ▼
Algo：ImageCodec 读取输入图片
    输出 Common.ImageBuffer
        │
        ▼
Algo：FilterRegistry 查找并依次执行滤镜
    resize → grayscale → 可选 watermark
    每步输入、输出均为自有像素数据
        │
        ▼
Algo：ImageCodec 写入任务专属的 output 文件
        │
        ▼
ViewModel 回到状态所属线程，更新 Object.BatchTask
    更新进度、结果路径和错误；全部完成后标为成功
        │
        ▼
UI：UiTaskPanel / UiPreview 展示进度与结果

失败：停止当前任务，标记失败并保留已生成结果，向用户说明部分完成。
取消：在图片或操作之间检查取消请求，释放临时缓冲并标记已取消。
任务完成、失败或取消后均释放运行资源，不直接从后台修改控件。
```

## 附录 B：关键设计决策记录（ADR）

| 决策 | 理由 |
|------|------|
| Algo 与 Object 并列，由 ViewModel 协调 | 算法不感知工程对象，模型不感知具体图像处理库 |
| 跨层使用 Common.ImageBuffer | 将 OpenCV 与 Qt 图像类型留在各自模块内部 |
| 操作参数与滤镜实现分离 | 工程可以保存操作序列，算法实现和插件可以独立替换 |
| 工程使用 JSON 加图片相对路径 | 示例结构便于阅读，不将像素缓存和运行对象写入工程 |
| 后台只处理数据，ViewModel 统一发布状态 | 避免工作线程更新控件或并发修改业务对象 |
| 插件先注销并销毁实例，再卸载动态库 | 避免正在执行或尚未释放的对象引用已卸载代码 |
| 输出使用任务 ID 与图片 ID，不覆盖输入 | 保留原始图片，便于查看与追踪多次处理结果 |
