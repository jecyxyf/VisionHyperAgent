# 项目需求与全局规划

## 目标

在进入编码前，把用户的想法整理成一致、可实施、可验证的软件全局规划。

## 工作流程

1. 理解用户目标、使用场景、目标平台、使用者和期望效果。
2. 查看现有文档、目录和关键模块，避免规划与当前实现冲突。
3. 输出产品需求：功能范围、用户交互、非目标、验收标准和优先级。
4. 输出技术框架：进程结构、前后端边界、数据流、状态流和关键技术选型。
5. 输出目录结构与模块定义：说明每个模块的职责、依赖关系和归属位置。
6. 输出接口定义：HTTP 路径、WebSocket 消息、请求/响应字段、错误码、超时和兼容策略。
7. 补充配置、日志、安全、跨平台、进程生命周期和部署约束。
8. 形成分阶段实施计划，并标记需要用户确认的高风险决策。

## 输出要求

- 方案要突出关键决策、取舍和影响范围，不写空泛套话。
- 结构和接口必须可落地，能直接指导后续编码。
- 需要长期保留的规划应沉淀到 docs/，不要只留在对话中。
- 存在高风险歧义时先提出少量关键问题，不做扩大式追问。

## 边界

- 本技能只做全局规划，不直接修改业务代码。
- 不擅自扩大需求范围，不引入未确认的第三方服务或依赖。
- 涉及目录结构落地时，应同时参考 project-rules/project-structure.md。
