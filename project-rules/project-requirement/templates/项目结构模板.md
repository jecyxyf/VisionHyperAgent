# <项目名称> 项目结构

> 在模块 API 完成后，依据已确认的架构、模块文档和仓库现状填写，输出到 `specs/REQ-003-项目结构.md`。下表是文档组织示例；按实际项目补充源码、测试、资源和构建目录，并标明尚未创建的规划项，不凭模板创建空目录。成品移除本段模板说明。

## 简介

## 一、目录结构与说明

| 层级 | 目录 / 文件 | 类型 | 简要说明 |
| :---: | :--- | :---: | :--- |
| 1 | **`<项目根目录>/`** | 根目录 | 项目工作目录 |
| 2 | `├── AGENTS.md` | 文档 | 按任务读取对应文档的路由；计划在最后阶段生成 |
| 2 | `└── specs/` | 目录 | 项目文档，临时开发计划单独存放于 plans/ |
| 3 | `　　├── 产品需求文档.md` | 文档 | 产品目标、用户、场景、功能、交互与验收，不包含技术实现 |
| 3 | `　　├── 技术方案设计.md` | 文档 | 已确认的技术架构、架构层、模块职责及依赖 |
| 3 | `　　├── 项目结构.md` | 文档 | 当前结构说明及规划文件位置 |
| 3 | `　　├── 代码规范.md` | 文档 | 语言规范与项目注释要求；计划在下一阶段生成 |
| 3 | `　　├── plans/` | 目录 | 临时开发计划与需求设计进度 |
| 4 | `　　│　└── 需求设计进度.md` | 文档 | 当前阶段、章节确认、模块产物和待同步事项，用于中断后继续 |
| 3 | `　　└── models/` | 目录 | 模块 API 文档集合，不是业务源码目录 |
| 4 | `　　　　└── <架构层名称>/` | 目录 | 名称与技术方案设计中的层保持一致 |
| 5 | `　　　　　　└── <模块名>.md` | 文档 | 对应模块的数据结构、属性、方法、消息、委托和完整调用示例 |

## 二、补充说明

- 模块文档直接存为 `specs/models/<架构层名称>/<模块名>.md`，不再嵌套同名模块目录。
- 临时开发计划文档统一存放在 `specs/plans/`，与正式需求、架构及模块 API 文档分开；不因目录规划而自动生成计划文件。
- `specs/plans/REQ-005-需求设计进度.md` 是本技能维护的轻量流程记录，不是业务开发实施计划；其中的状态不能替代正式文档里的需求和接口定义。
- 架构层和模块名称取自已确认的架构，不从模板 Demo 推断，不按代码仓库或包名另起一套分组。
- 模板资源内置于 `project-requirement/templates/`，不混入正式项目文档；若技能位于项目内，在目录表中按其实际路径补充说明。
- 不自动添加对话记录、调研资料或其他空目录；确有需求时按用户确认的位置补充。
- 代码规范和 AGENTS.md 实际生成后，更新目录表中的规划状态。其他未实现的源码目录仍须保留“规划”标识。
