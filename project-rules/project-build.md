# 代码编译与部署规则

## 目标

按项目已确认的需求和技术方案完成编译、打包与发布验证，并确保产物中没有私有数据或缺失依赖。

## 标准构建

构建入口、目标平台、产物形态和输出目录必须来自项目当前确认的文档；本规则不硬编码具体项目的发布结构。

构建前先核对：

- 产品需求文档中的交付形态
- 技术方案设计中的构建入口和产物目录
- 项目当前实际构建脚本或 CI 配置

没有明确构建入口或产物定义时，先向用户确认，不自行假设默认目录。

产物形态由项目需求决定，例如：

~~~text
<项目发布目录>/
├── <平台产物>        # 压缩包、绿色目录、安装包或单一可执行文件
└── <校验信息>        # 需要交付时生成大小与 SHA256
~~~

产物必须与项目确认的交付方式一致；不得因为构建工具方便而擅自把绿色目录压缩、拆散包结构或改变输出位置。

## 发布前检查

1. 确认发布产物中没有私有配置、日志、真实密钥、测试证据或本机数据。
2. 按目标平台保留必要权限，特别是 Linux 可执行权限。
3. 检查目标架构和动态依赖，确保不会在用户机器上缺失运行库。
4. 按项目声明的启动方式做冒烟验证，并确认退出后没有残留子进程。
5. 未完成实机验证时必须明确告知用户，不宣称发布验证通过。
6. 需要远程交付时输出产物大小和 SHA256，便于用户核对拷贝结果。

## 运行约束

- 发布包必须保持项目声明的完整目录结构，用户不能只复制主程序导致依赖缺失。
- 示例配置、真实配置、密钥和日志的存放规则以项目技术方案为准；含密钥的本机配置不得进入 Git 和发布包。
- 应用启动、界面找回、退出方式和子进程回收策略以项目技术方案为准；发布验证必须覆盖声明的生命周期。
- 冒烟验证产生的日志、临时文件和测试数据不得混入正式发布产物。
