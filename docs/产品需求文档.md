## 1. 产品定位与目标

VisionHyperAgent 是一个 Agent 驱动的视觉模型标注、自动训练与离线部署桌面软件。

软件帮助用户从未标注图片出发，通过与 Agent 交互完成初步标注，经人工修改和确认后，自动执行本机训练、调参和评估，输出最佳候选模型。模型在同一软件中部署运行，支持软件自行连接相机，也支持外部程序传图并取得识别结果。

产品目标：

1. 将标注、人工审核、自动训练和部署识别整合为一个软件内的连续流程。
2. 将训练配置、调参、评估和选模工作交给 Agent 自动完成。
3. 由软件自行管理运行环境，避免用户手动搭建 Conda/Python/PyTorch 环境。
4. 保持计算本地化：训练在本机 GPU 上执行，生产识别不依赖互联网或在线大模型。
5. 通过 ZeroMQ 提供简单的外部识别集成能力，并保留未来增加通信方式的边界。

### 2.1 界面与交互布局（2026-09-08 确认）

导航层级：

```text

  标注
  训练
设置
关于
```

- 去掉首页，打开软件默认进入运行页。
- “模型”既是独立模型库页面，也是标注、训练的父分组。文字与箭头在视觉上合并为一个导航项，共用背景和圆角；点击文字进入模型库，点击右侧箭头展开／折叠子导航；折叠不能切换当前页面或清空草稿。模型库展示当前模型目录下已训练模型的名称、格式与路径，提供目录选择和刷新入口。
- 运行页展示图像与识别结果；顶部提供模型选择、图像源配置与单次推理入口，不单独显示网络触发按钮；图像结果区不显示“未就绪”，底部并列展示图像源和当前运行模型名称。支持手动单次触发，也支持外部程序通过网络多次触发识别，具体协议契约仍待后续设计。
- 标注页顶部提供打开目录入口，浏览区支持批量预览图片与逐图标注。
- 训练页用于配置训练参数，展示训练效果曲线、进度与日志。没有真实训练数据时显示空状态，不虚构曲线或指标；Agent 自动调参方向不变。
- 设置、关于位于导航底部。聊天作为全局面板，切页保留输入与会话状态。Agent 标题栏移除连接状态和设置按钮，提供清除聊天记录图标；清除记录不清空尚未发送的输入草稿。
- 整体采用大胆、时尚的绚彩渐变磨砂风格，不采用灰白保守配色。蓝紫、洋红、青色与蜜桃色贯穿背景、玻璃面板、导航选中态、按钮、表格、曲线和输入框；以半透明层叠、玻璃高光、柔和投影体现材质，同时保证文字与数据可读。操作使用顶部小图标按钮并提供悬停说明。顶部保留“Agent驱动的视觉模型自动训练及部署平台”完整文案，不显示英文产品名称；采用 26–28px 强字重中文标题、渐变 Agent 铭牌与虹彩玻璃底座，突出“自动训练”。
- 清理常驻的工作区名称、预览／开发说明、版本号、重复面包屑和长篇引导。保留操作标签、参数、结果数据及必要连接状态；错误反馈按用户操作临时显示，可关闭且自动消失，不能用“成功”掩盖未执行。
- 界面当前不显示“实例分割”字样；这是展示调整，不改变 R-01 的业务范围。

以上是界面要求；当前 Slint 实现仅支持布局和本地状态预览，图片／模型目录读取、标注编辑、真实训练、推理和网络触发尚未接入。

### 2.2 关键术语与边界

- **一个软件**：首版保持一个主桌面程序，训练与推理统一使用和交付；内部允许私有 runtime、Codex 和 Python 执行进程，但不拆成前后端双主程序或需要用户分别配置的产品。
- **私有 runtime**：由软件定位和管理的运行环境，不依赖用户手动选择系统 Python 或激活 Conda。最终安装包形式尚未确定，不把“一个软件”擅自解释为所有内容必须静态链接成单一二进制。
- **在线训练**：Agent 的理解、交互和决策可以联网，但训练计算在本机。首版没有云端训练需求。
- **离线识别**：模型执行不依赖互联网或在线 Agent；不等于禁止本机或局域网中的图像通信。具体网络接入范围尚未确定。
- **不限显卡型号**：不设置型号白名单，不代表承诺所有历史 NVIDIA GPU 都支持某个软件版本。
- **最佳模型**：自动评估后选出的候选结果。具体评价规则、资源约束和终止条件尚未确定，不承诺全局最优或无限训练。

## 3. 首版用户流程

### 3.1 导入图片与交互式初标

1. 用户在软件中导入待标注图片。
2. 用户与 Agent 交互，说明待分割对象、类别和标注规则。
3. Agent 利用任务图片和用户要求生成初步实例分割标注。
4. 软件将初标呈现给用户，供其修改和确认。

实例分割结果必须能够区分不同对象实例，并表达实例所属类别与分割区域。矩形框不能替代实例分割区域。

**已确认边界：** 允许将任务图片发送给配置的在线大模型服务；不额外内置独立的辅助标注模型。官方 YOLO 技能属于 Agent 工作依赖，不能被省略，也不能被当作另一个辅助视觉模型。

**未决事项：** Agent 如何生成并交付可编辑轮廓、采用何种标注表达、怎样处理复杂轮廓，以及初标质量如何验收，均需后续验证。本 PRD 不把“使用 Agent”当作精度已经得到保证的证据。

### 3.2 人工修改与确认

用户需要能够：

- 查看图片及各实例的初始标注。
- 修改实例的类别和分割区域。
- 删除错误标注，补充漏标对象。
- 确认用于训练的标注结果。

用户确认是进入训练流程的业务前提。具体交互控件、快捷键、画布实现和标注文件格式不在本轮确定。

### 3.3 Agent 自动训练与选模

在用户确认标注并发起训练后，Agent 负责：

1. 制定并配置训练方案。
2. 调用本机私有 Python/PyTorch 环境中的 YOLO26 训练能力。
3. 自动调整参数并执行多轮候选训练。
4. 评估和比较候选模型。
5. 选出最终模型，导出到 Rust 生产推理所需的部署格式。

上述流程不要求用户逐轮手动设置参数、启动训练或比较候选模型。

“全部自动”不表示已确定无限试验、无条件重训或某个固定训练时长。评价指标、数据划分、搜索预算、重试与停止策略见未决事项；文档不预置未经用户确认的默认值。

### 3.4 同一软件中的离线部署

1. 软件加载已产出的部署模型。
2. 通过 Rust 推理模块处理输入图像。
3. 输出实例分割结果。

部署路径不调用在线 Agent，也不依赖启动 Python 训练进程。训练环境仍随同一软件提供，不因为采用 Rust 推理就拆分产品。

#### 相机路径

软件通过 OpenCV 连接相机、采集图像，再交给推理模块识别。相机品牌、采集后端、视频模式、并发路数和帧率要求尚未确定；不承诺任意相机均可接入。

#### 外部程序路径

外部程序通过 ZeroMQ 发送图片，软件调用模型识别，再通过 ZeroMQ 返回对应结果。结果需要能表达实例类别和分割区域，具体掩码/轮廓编码以及附加字段尚未确定。

两种图像入口应复用同一推理能力。是否把相机识别结果主动推送给外部程序，尚未决定。

## 4. 已选择的整体技术方向

### 4.1 方案 A：Python 训练，Rust 推理

| 逻辑部分 | 产品职责与技术方向 |
| --- | --- |
| 桌面应用 | Rust + Slint，统一承载交互、标注审核、训练与部署操作。 |
| Agent 接入 | 直接对接开源 Codex CLI，提供用户交互入口并纳入官方 YOLO 技能。具体 CLI 集成接口尚未确定。 |
| 训练执行 | 私有 Python/PyTorch 环境执行 YOLO26 训练、调参、评估和模型导出。 |
| 生产推理 | Rust 通过官方 `ultralytics-inference` 及 ONNX Runtime 路线加载导出模型并执行实例分割。 |
| 图像接入 | OpenCV 相机采集，以及 ZeroMQ 外部传图。 |
| 外部通信 | 首版只实现图片请求与识别结果返回，避免提前扩展成多协议系统。 |
| 环境管理 | 软件自行管理所需 runtime，并按软件发行版维护兼容要求。 |

这是逻辑职责划分，不是源码目录、进程协议、线程模型或数据库设计。

已确认采用模块化单体，按 View、ViewModel、Agent、应用、驱动／适配、基础六层组织职责；Python runtime 管理归基础层，训练调用适配归驱动层，业务状态归应用层。详细边界见[软件框架](软件框架.md)。各层具体模块后续设计，首版不建立前后端双主程序或内部 ZeroMQ 总线。

### 4.2 在线与离线责任

| 工作 | 执行位置与联网边界 |
| --- | --- |
| Agent 交互、图片理解和初标 | 允许调用配置的在线大模型服务，允许发送任务图片。 |

在线标注所允许发送的图片属于用户的任务数据。无关文件、运行环境、凭据不属于该图片处理授权范围。

## 5. 环境与交付要求

### 5.1 单软件与私有 runtime

软件交付物需提供正常使用所需的运行环境，由软件管理，不要求用户执行 pip/conda 命令或配置系统 Python。

此要求覆盖训练环境以及已选推理、图像采集和通信路线所需的运行依赖。具体是何种安装器、目录布局、资源包及更新机制，尚未选择。

离线部署开始前，模型和识别所需运行资源必须齐备；识别路径不能把临时联网下载依赖作为启动前提。训练初始权重、官方技能和 Codex 资源的具体分发与更新方式，仍需后续确认。

### 5.2 平台和硬件兼容

- 首版覆盖 Linux、Windows。
- NVIDIA 为首版 GPU 支持范围。
- 软件版本与相应运行时组合、兼容要求关联，启动时根据实际环境判断是否可运行。
- 不兼容时需要给出明确说明，不能只因品牌是 NVIDIA 就宣称可用。
- 不要求用户手动处理 Conda 环境，但不将此等同于任意宿主驱动都兼容。

操作系统最低版本、Linux 发行版范围、CPU 架构、GPU 架构要求及最低驱动版本，均未确定。

候选评价指标可考虑实例分割精度，并按业务需要增加推理耗时或资源约束；本轮不指定指标权重、数值阈值或排名算法。

| AC-06 | R-13、R-15、R-16 | 外部程序按约定协议通过 ZeroMQ 送入图片并收到对应实例分割结果，整个识别计算链路不依赖在线服务。 |
| AC-07 | R-05 | 软件依据自身版本对应的兼容要求检测实际 GPU/驱动，能够区分可运行与不兼容环境，而不是使用固定型号名单。 |
| AC-08 | R-09、R-17、R-18 | 同一业务操作从界面和 Agent 工具入口执行时，在相同前置条件与参数下遵循相同校验并产生一致业务状态；智能操作复用 Agent 工作流，不能绕过用户确认门槛。 |

初标轮廓质量、模型精度、推理速度、资源占用和跨后端一致性的量化门槛尚未定义，不能据此提前宣称达到生产质量。

## 8. 非目标与范围控制

### 8.1 当前工程骨架与界面设计阶段的边界

- 已允许创建单 Cargo 包、Rust 启动与分层入口、约定目录、忽略规则及最小验证代码。
- `src/depends/` 先作为依赖管理目录，不自动下载第三方代码、SDK 或预编译库。
- 已允许设计原生 Slint 界面与本地交互，不自动扩大到 Rust 宿主、Agent、训练、推理、标注、相机或通信业务接入。
- 不安装训练 runtime 或功能依赖，不下载模型，不执行训练、推理、导出或性能试验。
- 不自动生成实施计划、完整业务排期或未经确认的模块清单。

### 8.2 首版不纳入的产品能力

- 实例分割之外的独立视觉任务。
- 云端训练和分布式训练平台。
- 非 NVIDIA GPU 后端；CPU-only 训练和生产推理不作为本期要求。
- 额外部署独立辅助标注模型。
- ZeroMQ 之外的对外识别通信协议实现。
- 前后端两个主可执行程序，以及用于前后端通信的内部 ZeroMQ 总线。
- 为未来协议提前建设通用插件系统。
- 在 OpenCV 接入之外预先承诺厂商专有相机 SDK 适配。

未来扩展不能反向成为本轮文档初始化或首版需求的隐性实现任务。
