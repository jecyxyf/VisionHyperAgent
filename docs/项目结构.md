## 补充说明

- `docs/models/<架构层名称>/<模块名>.md` 是模块 API 的唯一正式路径；每份文档都包含数据结构、属性、方法、消息、委托、错误、生命周期、线程安全、依赖和完整调用 Demo。
- 架构层和模块名称必须与 `docs/技术方案设计.md` 一致。目录表中的 `ml-worker/`、`lib/stores/`、`bin/win/` 和 `bin/linux/` 是规划或发布位置，不因写入文档而创建空目录。
- 当前前端已有组件位于 `source/frontend/src/lib/components/`；结构规则要求新增页面放 `pages/`、可复用组件放组件目录、跨页面状态放 `lib/stores/`，不为迁移而无关重构已有文件。
- `source/backend/depends/` 是第三方依赖目录，禁止直接修改；若需要更新依赖，先通过技术方案和构建规则确定版本与来源。
- `data/`、`dist/`、`target/`、日志、真实 `app_config.json` 和构建缓存属于本机或构建产物，不作为正式源码和文档交付内容。
- Windows 产物进入 `bin/win/` 的 ZIP；Linux 产物进入 `bin/linux/` 的绿色目录。实际构建脚本完成前，现有历史压缩包只视为旧产物，不代表新发布结构已经验证。
- 任何新增模块必须同时更新架构文档、对应 API 文档、本结构文档和 `docs/plans/需求设计进度.md`；新增源码前先读取 `project-structure.md`。
