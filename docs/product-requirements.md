## 1. 产品定位

VisionHyperAgent 是一款 **Agent 驱动的视觉模型桌面软件**。用户通过自然语言描述识别目标，Agent 生成标注规则，系统完成数据标注、模型训练和离线部署的完整闭环。

**核心价值**：非算法人员也能完成从"描述目标"到"部署模型"的全流程，无需编写代码。

**目标用户**：
- 工业质检工程师（需要快速训练缺陷检测模型）
- 科研人员（需要小样本实例分割）
- 数据标注团队（需要 Agent 辅助提效）

## 2. 部署形态

### 2.1 交付物

单可执行文件，无需安装。

| 平台 | 文件名 | 大小预估 |
|------|--------|---------|
| Windows x64 | VisionHyperAgent.exe | 15-25 MB |
| Linux x64 | VisionHyperAgent | 15-25 MB |
| macOS arm64 | VisionHyperAgent | 15-25 MB |

### 2.2 启动行为

用户双击可执行文件后：

1. 进程启动，不显示终端窗口（Windows windows_subsystem）
2. 系统托盘出现 VisionHyperAgent 图标
3. 自动打开系统默认浏览器，访问 http://127.0.0.1:8420
4. 浏览器显示主界面

### 2.3 进程模型

~~~text
用户双击 VisionHyperAgent.exe
|
+-- 系统托盘（主线程，进程主人）
|   +-- 左键点击：打开/聚焦浏览器
|   +-- 右键菜单：打开界面 / 退出
|
+-- Rust 服务器（后台线程，端口 8420）
|   +-- HTTP：静态文件（前端产物已编入二进制）
|   +-- WebSocket：实时双向通信
|   +-- REST API：项目/模型/配置 CRUD
|
+-- Codex App Server（子进程）
    +-- 由 Rust 服务器 spawn
    +-- 父进程退出时自动终止（防孤儿）
~~~

### 2.4 退出策略

**唯一退出入口**：系统托盘右键菜单「退出」。

| 行为 | 结果 |
|------|------|
| 关闭浏览器标签页 | 后端继续运行，托盘仍在；重新打开可恢复状态 |
| 刷新浏览器页面 | WebSocket 重连，无感知 |
| 托盘右键→退出 | 停 Codex → 停服务器 → 移除托盘 → 进程退出 |
| 进程意外崩溃 | Codex 子进程被 OS 自动终止 |

### 2.5 防孤儿进程保证

| 平台 | 机制 |
|------|------|
| Windows | Job Object (JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE) |
| Linux | prctl(PR_SET_PDEATHSIG, SIGKILL) |
| macOS | setsid() 进程组 |

## 3. 核心功能模块

### 3.1 预标注（Pre-annotation）

**用户故事**：作为标注员，我描述要识别什么，Agent 帮我生成标注规则，确认后批量应用到图片。

**流程**：
1. 用户输入描述："识别电路板上的短路焊点，外观是锡堆过多，与正常焊点的区别是……"
2. Agent 分析描述，追问缺失信息（光照？尺寸？背景？）
3. Agent 生成结构化标注规则（目标类别/外观特征/排除条件）
4. 用户在界面上确认或修改规则
5. 规则保存，可应用于批量标注

**验收标准**：
- [ ] Agent 能解析中英文混合描述
- [ ] 追问至少覆盖：目标外观、类别区分、排除情况
- [ ] 规则以结构化 JSON 存储，可版本管理
- [ ] 描述变更后旧规则自动标记为失效

### 3.2 预训练（Pre-training）

**用户故事**：预标注效果不足时，用少量已确认数据训练辅助模型，提高批量标注效率。

**流程**：
1. 系统检测已确认标注数据量（目标 >= 50 张）
2. 用户点击「开始预训练」
3. 系统在本机 GPU 训练种子模型
4. 训练完成后自动应用于后续批量标注

**验收标准**：
- [ ] 支持从 50 张图片开始训练
- [ ] 训练过程不阻塞 UI，关闭浏览器不影响训练
- [ ] 训练进度实时推送到浏览器
- [ ] 训练失败时给出明确错误原因

### 3.3 标注（Annotation）

**用户故事**：标注员在画布上绘制实例分割遮罩，逐图确认形成训练数据集。

**画布工具**：

| 工具 | 操作 | 快捷键 |
|------|------|--------|
| 画笔 | 拖拽绘制自由遮罩 | B |
| 多边形 | 逐点绘制多边形区域 | P |
| 擦除 | 擦除遮罩区域 | E |
| 智能选择 | 点击目标自动生成遮罩（预训练后可用） | S |
| 缩放 | 滚轮/捏合 | 滚轮 |
| 平移 | 空格+拖拽 | 空格 |

**画布图层**（从下到上）：

~~~text
Layer 0: 底图（原始图片）
Layer 1: 已确认遮罩（半透明彩色，不可直接修改）
Layer 2: 绘制中路径（当前操作实时预览）
Layer 3: UI 叠加（选中框/控制点/十字线/网格）
~~~

**验收标准**：
- [ ] Canvas 2D 渲染，4K 图片 60fps
- [ ] 支持撤销/重做（至少 50 步）
- [ ] 多实例分割遮罩独立存储
- [ ] 遮罩可导出为 COCO / YOLO 格式
- [ ] 画布操作不影响底图层

### 3.4 训练（Training）

**用户故事**：基于已确认的数据集版本发起模型训练，Agent 制定调参方案。

**流程**：
1. 用户选择已确认的数据集版本
2. Agent 分析数据分布，建议模型架构和超参
3. 用户确认后开始训练
4. 训练在本机 NVIDIA GPU 执行
5. 多轮评估后登记最佳候选模型

**验收标准**：
- [ ] 支持 YOLO 系列模型（通过 ultralytics 子模块）
- [ ] 训练任务队列化，同一 GPU 串行执行
- [ ] 训练指标（loss/mAP/学习率）实时推送到浏览器
- [ ] 训练期间关闭浏览器不中断训练
- [ ] 最佳模型自动登记到模型库

### 3.5 离线部署（Inference）

**用户故事**：使用导出的模型执行识别，不依赖在线 Agent 和训练进程。

**流程**：
1. 用户从模型库选择已训练模型
2. 导出为 ONNX / TensorRT 格式
3. 加载导出模型，对单张或批量图片执行推理
4. 显示识别结果（遮罩/置信度/类别）

**验收标准**：
- [ ] 推理完全离线，不调用任何在线 API
- [ ] 单张 4K 图片推理延迟 < 500ms（含前后处理）
- [ ] 批量推理支持进度显示和中断
- [ ] 结果可导出为 COCO JSON / mask PNG

## 4. 前后端通信协议

### 4.1 HTTP REST（低频）

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/projects | GET | 项目列表 |
| /api/projects | POST | 创建项目 |
| /api/projects/:id/datasets | GET | 数据集列表 |
| /api/models | GET | 模型列表 |
| /api/models/:id/export | POST | 导出模型 |
| /api/config | GET/PUT | 用户配置 |

### 4.2 WebSocket（实时）

消息格式：JSON

~~~json
{
  "type": "agent.message_delta",
  "data": {
    "thread_id": "xxx",
    "content": "分析中..."
  }
}
~~~

**前端到后端**：

| type | 说明 |
|------|------|
| ping | 心跳（每 10 秒） |
| agent.start_turn | 发送用户输入给 Agent |
| annotation.confirm | 确认标注结果 |
| training.start | 启动训练 |
| training.stop | 停止训练 |

**后端到前端**：

| type | 说明 |
|------|------|
| pong | 心跳响应 |
| agent.message_delta | Agent 回复增量 |
| agent.turn_completed | Agent 回合完成 |
| training.progress | 训练进度更新 |
| training.completed | 训练完成 |
| error | 错误通知 |

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
|------|------|
| 4K 图片标注画布帧率 | >= 60fps |
| WebSocket 消息延迟 | <= 16ms（本地） |
| 单张图片推理 | <= 500ms |
| 100 张图片批量标注 | <= 5 分钟（有辅助模型） |
| 启动到界面可用 | <= 3 秒 |
| 可执行文件大小 | <= 30MB |

### 5.2 安全

- 仅监听 127.0.0.1，不暴露到局域网
- API Key 存储在用户本地（~/.vision-hyper-agent/），不上传
- 训练数据不出本机

### 5.3 数据存储

| 数据 | 位置 | 格式 |
|------|------|------|
| 项目配置 | ~/.vision-hyper-agent/projects/ | JSON |
| 标注数据 | 项目目录/annotations/ | COCO JSON + mask PNG |
| 训练模型 | 项目目录/models/ | PyTorch / ONNX |
| 用户设置 | ~/.vision-hyper-agent/config.json | JSON |
| 日志 | ~/.vision-hyper-agent/logs/ | 文本文件 |

## 6. 技术选型

| 层 | 技术 | 理由 |
|----|------|------|
| 前端框架 | Svelte 5 + TypeScript | 编译时框架，产物小，无 VDOM 开销 |
| 标注画布 | Canvas 2D API | 2D 标注任务，Three.js 不适用 |
| 构建工具 | Vite 6 | 秒级热更新，生态成熟 |
| 后端框架 | Rust + axum 0.8 | 类型安全，单二进制，异步模型清晰 |
| 静态资源嵌入 | rust-embed | 前端产物编入二进制，单文件分发 |
| 系统托盘 | tray-icon 0.19 | 跨平台，Tauri 团队维护 |
| WebSocket | axum ws + tokio-tungstenite | 服务端/客户端各一层 |
| 子进程管理 | tokio::process + libc | 防 orphan，跨平台 |
| 训练框架 | ultralytics（子模块） | YOLO 系列，GPU 支持 |

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Codex App Server 协议变更 | Agent 功能中断 | 方法白名单+版本锁定 |
| GPU 驱动兼容性 | 训练失败 | 启动时检测 CUDA 可用性 |
| 大图片内存占用 | OOM | 分块加载+金字塔瓦片 |
| 浏览器兼容性 | 旧浏览器无法使用 | 仅支持 Chrome/Edge >= 120 |
| Windows 托盘兼容性 | 托盘不显示 | 降级为命令行模式 |
