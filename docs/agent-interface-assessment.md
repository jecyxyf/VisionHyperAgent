# Agent 界面功能需求与现状评估

| 项目 | 内容 |
|---|---|
| 版本 | 0.1 |
| 日期 | 2026-09-16 |
| 范围 | 只评估前端界面承载能力，不评估后端 WebSocket、CodexAgent 或业务逻辑实现 |
| 当前基准 | 复刻版界面，分支 `v0.1.1`，提交 `f95f00e` |

---

## 1. 结论

当前 Agent 界面已经满足 **全局入口和基础聊天壳**，但还不满足 Agent 作为产品核心助手所需的完整交互形态。

### 已经满足

- 右侧全局 Agent 面板位置。
- 基础消息列表容器。
- 输入框和发送按钮。
- Enter 发送、Shift+Enter 换行。
- 空状态提示。
- 清空当前本地消息。
- 通过 Splitter 调整面板宽度。
- 模型选择和 Effort 选择 Combobox。
- 历史会话的界面级新建、切换和删除交互。
- 拖拽添加附件、附件卡片展示和删除交互。
- 预标注、标注、训练页面已有 Agent 相关按钮入口。

### 主要缺口

- 缺少 Agent 连接状态和回合状态。
- 缺少流式回复、生成中、失败、重试、停止等过程反馈。
- 缺少 Agent 追问交互。
- 缺少结构化标注规则卡片。
- 缺少规则确认、修改、版本和失效状态。
- 右侧 Agent 面板与预标注、标注、训练页面之间没有上下文联动。
- 历史会话目前仅是前端 mock，缺少持久化恢复；权限确认也未实现。

一句话概括：

> 当前界面是“可输入的 Agent 面板骨架”，还不是“可承载完整 Agent 工作流的界面”。

## 2. 评估状态说明

| 状态 | 含义 |
|---|---|
| 已满足 | 界面位置、布局和基础交互已经存在，可直接承载该需求 |
| 部分满足 | 入口或容器已经存在，但缺少关键状态、内容形态或联动 |
| 未满足 | 当前界面没有对应承载区域或交互形态 |

| AGT-22 | Effort Combobox | 在 Agent 输入区底部提供低 / 中 / 高 Effort 选择 | 已满足（界面层） | 尚未接入真实 Agent 配置 |

### 用户确认的 Agent 面板布局

~~~text
┌─────────────────────────────┐
│ Agent        [历史] [清空]  │
├─────────────────────────────┤
│                             │
│        聊天消息区域          │
│                             │
├─────────────────────────────┤
│ [附件1 ×] [附件2 ×]          │
│ ┌───────────────────────┐   │
│ │ 输入消息…              │   │
│ │                       │   │
│ │ [模型▾] [Effort▾] [发送/停止] │
│ └───────────────────────┘   │
└─────────────────────────────┘
~~~

布局约束：

- 模型选择和 Effort 位于输入框底部，与发送 / 停止按钮同属 Composer 控件区。
- 发送与停止共用一个主按钮，根据当前回合状态切换图标和文案。
- 附件区域位于 Composer 上方。
- 附件只能通过拖拽放入 Agent 面板，不引入额外的附件上传按钮。
- 图片附件展示缩略图，普通文件展示文件图标。
- 每个附件都有独立删除按钮。

## 5. 关键缺口分析

### 5.1 状态与过程反馈缺失

用户无法从界面判断：

- Agent 是否可用。
- 消息是否已经发送。
- Agent 是否正在处理。
- 回复是否还在生成。
- 任务是否失败。
- 失败后能否重试。

这会导致 Agent 面板看起来像静态表单，而不是可信赖的助手。

### 5.2 预标注结果形态缺失

Agent 的核心价值不是输出一段文字，而是输出可确认、可修改、可复用的结构化标注规则。

当前缺少：

- 目标类别字段。
- 外观特征字段。
- 类别区别字段。
- 排除条件字段。
- 置信度或完整性提示。
- 规则版本。
- 用户确认状态。
- 旧规则失效提示。

### 5.3 页面联动缺失

当前右侧 Agent 面板和中央页面是割裂的。

期望关系：

```text
右侧 Agent 面板：负责自然语言对话、追问、解释
中央业务页面：负责结构化结果、确认和执行
```

例如：

- 在预标注页，Agent 分析结果写入 Agent 分析区域。
- 生成规则后，规则卡片写入标注规则区域。
- 用户确认规则后，才允许进入标注流程。
- 在训练页，Agent 建议写入参数建议卡片，用户确认后应用到表单。

## 6. 界面优化优先级

### P0：补齐 AgentPanel 基础状态

目标：让 Agent 面板看起来像真实助手，而不是静态演示。

需要增加：

1. 顶部状态胶囊。
2. 用户消息、Agent 回复、系统提示、错误提示四类样式。
3. 发送中、生成中、完成、失败四种回合状态。
4. 停止按钮。
5. 失败后的重试入口。

### P1：补齐预标注工作流界面

目标：让 Agent 的输出能进入业务确认流程。

需要增加：

1. Agent 追问卡片。
2. 缺失信息列表。
3. 结构化标注规则卡片。
4. 规则字段编辑。
5. 确认、拒绝、重新生成按钮。
6. 规则版本和失效状态。

### P2：补齐页面联动界面

目标：让 Agent 与核心业务页面形成闭环。

需要增加：

1. Agent 面板顶部显示当前上下文。
2. 预标注页展示 Agent 分析结果。
3. 标注页展示初标生成过程和应用入口。
4. 训练页展示参数建议卡片和一键应用。

### P3：补齐恢复与安全界面

目标：让界面具备长期使用和本地安全意识。

需要增加：

1. 历史会话列表。
2. 刷新后的会话恢复状态。
3. 任务恢复提示。
4. 本地文件或命令执行权限确认卡片。

## 7. 建议新增或拆分的界面组件

为避免 `AgentPanel.svelte` 变成大型组件，建议后续拆分：

```text
source/frontend/src/lib/components/agent/
├── AgentStatusPill.svelte
├── AgentMessage.svelte
├── AgentMessageList.svelte
├── AgentComposer.svelte
├── AgentQuestionCard.svelte
├── AgentRuleCard.svelte
├── AgentResultPanel.svelte
└── AgentPermissionCard.svelte
```

### 组件职责

| 组件 | 职责 |
|---|---|
| AgentStatusPill | 展示连接状态和当前回合状态 |
| AgentMessage | 单条消息的视觉样式和内容展示 |
| AgentMessageList | 消息列表、滚动、加载更多 |
| AgentComposer | 输入区、发送、停止、重试 |
| AgentQuestionCard | Agent 追问和用户回答 |
| AgentRuleCard | 结构化标注规则展示与编辑 |
| AgentResultPanel | 页面内 Agent 分析结果区域 |
| AgentPermissionCard | 本地文件或命令权限确认 |

## 8. 界面验收标准

完成 P0 后，应满足：

- 用户能明确看到 Agent 当前状态。
- 用户能区分用户消息、Agent 回复、系统提示和错误提示。
- 用户能看到生成中状态。
- 用户能停止生成。
- 失败后能看到原因并重试。

完成 P1 后，应满足：

- Agent 能以卡片形式展示追问。
- 用户能逐项补充缺失信息。
- Agent 能以结构化卡片展示标注规则。
- 用户能修改并确认规则。
- 规则有版本和失效状态。

完成 P2 后，应满足：

- Agent 面板显示当前页面上下文。
- 预标注页能承接 Agent 分析结果。
- 标注页能承接初标生成结果。
- 训练页能承接参数建议结果。

完成 P3 后，应满足：

- 用户能找到历史会话。
- 刷新后能恢复当前任务状态。
- 涉及本地文件或命令执行时有明确确认入口。

## 9. 当前评估的边界

本文只评估界面，不代表以下内容已经实现：

- 前端 WebSocket 真实接入。
- 后端 `agent.start_turn`、`agent.message_delta`、`agent.turn_completed` 处理。
- CodexAgent 连接 Codex App Server。
- Agent 追问逻辑。
- 标注规则生成逻辑。
- 训练参数建议逻辑。

后续实施功能时，应以本文作为界面结构参考，再结合 `docs/product-requirements.md` 和 `docs/architecture.md` 补齐通讯与业务链路。
