## 7. 使用示例与约束

### 7.1 使用示例

```rust
use vision_hyper_agent::agent::{AgentError, SkillCatalog, SkillManager};

async fn inspect_skills(skills: &SkillManager) -> Result<SkillCatalog, AgentError> {
    // 调用方同时处理 items 与 issues，不把局部失败当作完整成功。
    skills.list().await
}
```

仅为接口使用示意，未编译或执行；调用方需提供已声明的输入和异步运行上下文，不依赖 Slint 事件循环。

### 7.2 使用约束

- Skill 描述如何使用能力；真实执行由注册工具及宿主提供，不在技能管理类中实现标注或训练。
- 模型不能通过 Skill 获得被禁止的内置终端或任意文件读写能力；库内部受控读取资源不等于向模型开放文件工具。
- 只管理已配置的来源，不继承开发者个人 Codex 配置、KEY 或插件安装。
- VisionHyperAgent 宿主只传入可执行文件所在目录下的 Skill。通用库的路径注入不等于本软件提供任意来源或运行中改目录功能。
- 查询缓存和 SkillCatalog 只是上游发现结果的投影，不再建立独立的技能执行或持久化系统。路径校验须考虑规范化和链接解析，不能仅用字符串前缀判断受控范围。
- 当前不增加 create、install、delete、enable 等尚未确认的管理接口。

**待确认事项：**

- 在禁用内置执行工具的前提下，Skills 指令和自定义工具能否完整协作。
- 扫描刷新对当前会话和后续轮次的影响，以及技能路径冲突的处理细节。
- 官方 YOLO 技能的最终来源版本和分发方式；此处不安装或下载。
- 固定 Skill 目录缺失或不可读时的处理，以及如何限制上游其他默认发现来源；只过滤展示列表不能证明模型实际只加载了允许来源。

目标平台为 Linux、Windows，尚未开展跨平台验证。软件版本与运行环境兼容范围沿用项目基线，不在本文填写未经确认的最低版本或资源限额。
