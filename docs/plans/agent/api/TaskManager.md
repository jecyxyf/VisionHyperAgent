#### 4.2.1 `submit(session_id, message)`

**说明**：提交一条图文对话请求，并将其交给串行调度。

**定义**：

```rust
pub async fn submit(&self, session_id: SessionId, message: AgentMessage) -> Result<TaskId, AgentError>
```

**参数**：

| 参数名 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| session_id | SessionId | 请求绑定的会话 | 提交后不能受界面会话切换影响 |
| message | AgentMessage | 文字和图片输入 | 至少有一项有效内容；格式与大小限制尚待确认 |

**返回值**：已受理请求的 TaskId；不表示模型已经回复或业务执行成功。

**错误**：

| 错误或失败状态 | 触发条件 | 失败后的状态 | 调用方处理 |
| --- | --- | --- | --- |
| `NotInitialized / InvalidState` | 未完成初始化、正在停止或已关闭 | 请求未被执行 | 等待可用状态或结束使用该实例 |
| `InvalidInput` | 消息为空、附件无效或会话参数不合法 | 不加入执行队列 | 修正输入 |
| `Backend / Transport / Io` | 上游调用、通信或存储失败 | 以实际结果为准，不能推定已回滚 | 接收错误并按业务规则处理，不自动重放有副作用的请求 |

**备注**：
- 一次仅执行一条用户对话请求，其余按提交顺序等待。
- 消息和附件必须能够支撑后续执行及手动重试；具体复制、缓存及清理方案尚待确认。
- 只允许发送本请求授权的任务图片，不把任意文件路径视为上传授权。

**说明**：取消指定等待请求，或向正在执行的指定请求发出停止控制。

**定义**：

**参数**：

| --- | --- | --- | --- |

**错误**：

| 错误或失败状态 | 触发条件 | 失败后的状态 | 调用方处理 |
| --- | --- | --- | --- |
| `NotFound / InvalidState` | 请求未知或不允许该取消操作 | 不误停其他请求 | 根据实际请求状态处理 |

- 排队请求取消后不发送给模型；运行中请求进入取消请求阶段，不能立刻宣称已经结束。

- 停止 Agent 请求不等于宿主工具已停止；已发生的副作用不自动回滚。
- 对已完成请求重复取消的细节尚待确认。

## 5. 事件与消息处理

### 5.1 事件与通知

| 名称 | 载荷类型 | 触发条件 | 说明 |
| --- | --- | --- | --- |
| TaskChanged | TaskInfo | 排队、开始、等待工具或取消状态变化 | 状态以后台实际变化为准 |
| MessageDelta | TaskId、SessionId、所属条目标识与消息片段 | 接收到允许展示的流式输出 | 不把同一请求中的不同输出项混成一条消息；片段不代表最终成功 |
| TaskFinished | TaskInfo | 请求进入成功、失败或已取消的终态 | 失败后保留输入，继续后续队列 |

事件进入 Agent 的统一事件出口，不由本模块直接回调 Slint。每条请求相关事件带有 TaskId 与 SessionId，迟到事件不能混入另一条请求。

同一请求可以产生多个输出项，流式片段还须保留对应条目标识；公开条目类型与最终结果结构仍待确认。工具结果、进度和最终回复不能仅按到达顺序无条件拼接为一个字符串。

### 5.2 消息处理与回调

Runtime 根据本模块队列选取请求，映射到 Codex turn；接收上游响应和事件后更新本模块状态。请求发出期间必须持续消费事件，不能用阻塞等待模型完成的方式阻塞取消或工具结果。

公开句柄经 AgentTransport 提交命令；取消和工具回传走可及时处理的控制路径。通信层只维护 CommandId 与等待者的关联，本模块仍是 TaskId、用户请求队列和请求状态的唯一归属。

#### 6.2.3 `AgentImage`

图片输入的候选表达，兼顾文件导入与剪贴板等内存来源。具体格式校验与资源策略尚待确认。

| Bytes | 图片字节及媒体类型 | 不依赖 UI 对象；不能仅凭媒体类型字符串信任输入 |

#### 6.2.4 `TaskState`

请求状态候选集合，与 AgentState 分开。

| 成员 | 类型／取值 | 说明 |
| --- | --- | --- |
| Queued | 等待 | 未发起对应模型轮次 |
| Running | 执行中 | 已进入模型轮次 |
| WaitingForTool | 等待工具 | 宿主工具尚未返回；该状态不表示其他排队请求可以并行执行 |
| CancelRequested | 正在停止 | 已发送取消控制，尚未确认终态 |
| Succeeded / Failed / Cancelled | 终态 | 分别依据真实结束结果；工具失败不一定立即等于整条请求失败 |

#### 6.2.5 `TaskInfo`

只读请求快照，详细结果与错误内容应使用本库类型并经过必要脱敏。

| 成员 | 类型／取值 | 说明 |
| --- | --- | --- |
| id / session_id | TaskId / SessionId | 请求与会话关联 |
| state | TaskState | 当前请求状态 |
| result | `Option<TaskResult>` | 最终输出；没有结果时不伪造默认成功 |
| error | `Option<AgentError>` | 请求失败原因；日志、事件不能泄露 KEY |

#### 6.2.6 `TaskResult`

最终模型回复及必要的结构化产物引用。字段随对话输出契约继续确认；不得把 Agent 的自然语言“完成”直接转换为宿主业务成功。

## 7. 使用示例与约束

### 7.1 使用示例

```rust
use vision_hyper_agent::agent::{AgentError, AgentMessage, SessionId, TaskId, TaskManager};

async fn send_text(tasks: &TaskManager, session_id: SessionId, text: String)
    -> Result<TaskId, AgentError>
{
    tasks.submit(session_id, AgentMessage { text: Some(text), images: vec![] }).await
}
```

仅为接口使用示意，未编译或执行；调用方需提供已声明的输入和异步运行上下文，不依赖 Slint 事件循环。

### 7.2 使用约束

- 一个运行实例先采用统一的串行用户请求队列；是否需要多个独立队列属于后续需求，不默认并行。
- 请求失败后继续处理后续队列；重试仅由用户发起。
- 清空聊天显示不停止任务、不清空输入草稿、不重置会话。
- 内部任务状态只实现一份；Runtime 持有或驱动该状态不代表另建一套状态机。
- 对外 TaskManager 是功能访问句柄，队列和请求状态属于本模块的后台部分；句柄克隆不会复制队列。Runtime 只驱动同一份状态，ViewModel 只维护显示投影。
- 不实现训练排名、模型选择或宿主业务任务队列。

**待确认事项：**

- 队列容量、输入大小、保留周期、超时与关闭时未完成请求策略。
- 新 TaskId 重试规则与工具副作用的重复执行保护。
- 取消与正常完成发生竞争时的终态判定；一条请求不能同时被记录为成功和已取消，具体判定依据须在实现前确认。
- 图片复制或借用、失败后可用性、与 Codex 历史附件保存的衔接。
